基于 **Distributed Lite Scheduler V1**（scheduler 控制面 + worker 执行面、MySQL + Redis、DAG 工作流、三套调度策略）的实现，下面整理 **30 道** 面试向技术问题，覆盖架构、分布式一致性、调度算法、工作流、安全与运维，难度由浅入深、面要广。

---

## 一、架构与整体设计（5 题）

1. **为什么把系统拆成 `scheduler` 和 `worker` 两个 Spring Boot 模块？控制面与执行面分离后，带来了哪些一致性、安全性和运维上的代价？**

2. **`in-process` 与 `remote` 两种 `task.executor.mode` 在调用链、故障域和水平扩展能力上有什么本质区别？生产环境你会如何选型？**

3. **架构文档里写「DAG 引擎只负责哪一层该提交，调度器负责 PENDING→RUNNING 与选点，执行器负责真正跑任务」。若面试官让你画一张职责边界图，你会如何论证这种分层避免了「上帝类」？**

4. **与 Airflow、DolphinScheduler、Kubernetes Job/CronJob 相比，本项目的定位差异是什么？哪些能力是刻意不做的（例如动态 DAG、容器编排级调度）？**

5. **若要把当前单体 scheduler 拆成「API 服务 + 独立调度器进程 + 工作流编排服务」，你会按哪些边界切？现有代码里哪些耦合点会成为拆分阻力？**

## 二、分布式调度与并发（6 题）

6. **FIFO、Priority、ResourceAware 三套调度器都带有 `@Scheduled` 循环，且各自使用不同的 Redis Leader 锁 key（如 `scheduler:leader:lock`、`scheduler:priority:leader-lock`）。三套同时启用时会出现什么问题？你会如何改成「可配置、互斥、单策略」？**

7. **Leader 选举使用 Redisson `tryLock(0, 30, TimeUnit.SECONDS)`：leaseTime 30s、调度周期约 5s，若 Leader 进程 GC 停顿超过 30s 会发生什么？这与「脑裂后双 Leader 同时调度」的风险如何权衡？**

8. **单任务调度除 Leader 锁外还有任务级分布式锁。请说明：没有任务锁时，两个调度周期可能对同一 `task_instance` 做什么重复操作？资源预留与状态更新会出现怎样的竞态？**

9. **`TaskInstanceServiceImpl` 用乐观锁（version 字段）做状态流转，而调度侧用 Redisson 锁。为什么同一实体上混用两种并发控制？各自适合解决哪类冲突？**

10. **状态机允许 `FAILED/TIMEOUT → PENDING` 重试，且更新时校验 `retryCount` 与 `maxRetryTimes`。若 Worker 迟到回调在任务已终态后到达，代码如何处置？这种设计与 At-least-once 语义如何对齐？**

11. **多 scheduler 实例部署时，`TaskSubmitService` 的内存削峰队列是否成为单点语义？实例重启后队列中未落库任务会怎样？你会如何改成分布式安全的提交缓冲？**

## 三、调度算法与资源管理（5 题）

12. **FIFO 按 `submit_time` 扫描 PENDING 任务；Priority 调度强调「有效优先级」与等待时长。请设计一种防饥饿（starvation）策略，并说明应改 SQL 排序还是应用层逻辑。**

13. **ResourceAware 调度中的 BestFit 选点逻辑涉及 CPU/内存/GPU、`NodeType`、亲和性与 `excludeNodeIds`。请口述：无可容纳节点时是跳过本轮还是标记失败？对集群利用率有何影响？**

14. **`dispatch` 失败后的 `rollbackAfterDispatchFailure` 会把状态打回 PENDING 并回滚预留。若回滚成功但 Worker 实际已收到请求并开始执行，系统处于什么不一致状态？如何检测与修复？**

15. **资源配额（Quota）、资源槽位（Slot）、资源使用记录（Usage）三者的关系是什么？`QuotaExceededException` 与 `ResourceQuotaInvariantException` 分别对应哪类不变量被破坏？**

16. **Worker 通过 `/api/resource/register` 与 heartbeat 上报存活。心跳超时后节点标记离线，其上 RUNNING 任务如何处理？与 K8s 的 Node NotReady + Pod 驱逐有何异同？**

## 四、DAG 工作流与事件驱动（6 题）

17. **工作流定义存于 `workflow.dag_json`，实例化时快照 `execution_plan`。为什么要快照而不是每次执行时重新拓扑排序？定义变更后旧实例行为应如何？**

18. **层（layer）内并行、层间串行的推进依赖 Redis Stream 上的任务完成事件，而非轮询 DB。请对比 Stream 与定时扫表的延迟、重复消费、宕机恢复各有什么优劣。**

19. **`TaskCompletionStreamHandler` 在层内任务全部终态后才触发下一层。若同一层两个任务几乎同时 SUCCESS，并发 handler 会不会重复投递下一层？你们用了什么幂等手段？**

20. **`WorkflowConditionalLayerGate` 与 `ConditionEvaluator` 如何决定分支 SKIPPED？条件表达式求值失败、或上游任务 FAILED 时，与 `FailureStrategy.STOP_ON_FAILURE / CONTINUE_ON_FAILURE` 如何交互？**

21. **工作流 pause / resume / cancel 与正在 RUNNING 的单任务如何协调？resume 后应从哪一层、哪个快照状态恢复？**

22. **`retry-failed` / `rerun` 与单任务 `FAILED→PENDING` 重试在工作流维度有何不同？`workflow_task_instance` 与 `task_instance` 的状态如何对齐？**

## 五、执行链路与 Worker（4 题）

23. **远程模式下 `RemoteTaskDispatchService` → `WorkerHttpClient` → Worker 异步线程池 → `SchedulerCallbackClient` 回调 internal API。请分析这条链路上每一步可能丢消息或重复上报的环节。**

24. **Worker 侧 `ProcessExecutionHelper` 处理子进程超时与销毁；Docker 执行与 Shell/Python 在隔离性、资源计量、清理成本上有何差别？**

25. **`TaskTimeoutWatchdog` 与 Worker 本地超时谁先触发？两者结论不一致（一方 TIMEOUT、一方 SUCCESS）时以谁为准？**

26. **`ParameterTemplateResolver` 如何解析任务参数模板？若 DAG 中下游要引用上游任务 stdout，你会扩展哪些表结构与 API？**

## 六、安全、多租户与数据（4 题）

27. **JWT 保护业务 API，`X-Internal-Token` 保护 `/api/internal/**`，`X-Worker-Token` 保护 Worker 下发接口。为何不能统一用一种 Token？内部接口若被误暴露到公网，风险边界是什么？**

28. **租户（Tenant）、项目（Project）、工作流权限（`WorkflowSecurityAspect`）的鉴权链路是怎样的？切换租户后 JWT 里应携带哪些 claim？**

29. **`DistributedWorkflowCacheManager`（Caffeine + Redis 失效）缓存了什么？缓存与 DB 不一致时，工作流推进会出现哪种可见性问题？**

30. **若要求「同一工作流实例内任务状态变更」可审计、可回放，现有 `task_status_change_log` 是否足够？你会如何设计事件溯源（Event Sourcing）或 outbox 表来对接外部监控系统？**
