```mermaid
    api --> sec --> biz
    SUBMIT_S --> sched

    MODE -->|in-process| INPROC --> LOCAL_RUN --> EXEC_REG
    MODE -->|remote| REMOTE --> WORKER_HTTP
    TI_S --> PUB --> STREAM --> LISTEN --> HANDLER --> DISPATCH

    LEADER --> REDIS[("Redis")]

```

**设计要点：**

- **DAG 引擎**只负责「哪一层、哪些节点该提交」，不直接管 CPU/选点。
- **调度器**负责 PENDING→RUNNING、配额、选节点、资源预留。
- **执行器**负责真正跑任务（本机或远程 Worker）。
- **工作流下一层**不靠轮询，靠 **Redis Stream** 上的任务完成事件驱动。

## 4. 单任务生命周期（核心数据流）

```mermaid
sequenceDiagram
    autonumber
    participant Client as 客户端
    participant API as TaskSubmitController
    participant Queue as TaskSubmitService<br/>内存队列
    participant DB as MySQL
    participant Sch as 调度器<br/>FIFO/Priority/ResourceAware
    participant Slot as ResourceSlotService
    participant Disp as TaskDispatchService
    participant Exec as 执行器<br/>in-process 或 Worker
    participant TI as TaskInstanceService
    participant Stream as Redis Stream

    Client->>API: POST /api/task-submit/submit
    API->>Queue: 入队削峰
    Queue->>DB: 批量写入 task_instance (PENDING)

    loop 每 5s @Scheduled
        Sch->>DB: 扫描 PENDING 任务
        Sch->>Sch: Leader 锁 / 任务锁
        Sch->>Slot: 配额检查 + 资源预留
        Sch->>DB: PENDING → RUNNING
        Sch->>Disp: dispatch()
    end

    alt in-process
        Disp->>Exec: 本地线程池 + LocalTaskRunner
        Exec->>Exec: Shell/Python/Docker 子进程
    else remote
        Disp->>Exec: WorkerHttpClient POST /api/worker/runs
        Exec->>Exec: Worker 异步执行
        Exec->>TI: 回调 X-Internal-Token
    end

    Exec->>TI: 状态 SUCCESS/FAILED/TIMEOUT
    TI->>DB: 更新 + 状态变更日志
    TI->>Stream: 发布 TaskCompletionEvent（若属工作流）
```

## 8. 架构一句话总结

> **scheduler** 是「大脑」：存元数据、编排 DAG、选资源、改状态、推事件；**worker** 是「手脚」：在独立进程里跑任务并回调；**MySQL** 记事实，**Redis** 管并发与异步推进；**in-process** 适合开发，**remote** 适合水平扩展。
